MessageFlags.IsComponentsV2

Every reply is a Components V2 card

Not embeds with a colour bar. Containers, sections, separators and action rows — clamped to Discord's hard limits before anything is sent: 40 components, 4000 characters, 10 top-level. If the converter ever throws, the original payload is sent instead, so a rendering bug degrades the look — never the feature.

src/ui/cv2.js
components: 40, // per message, nested included topLevel: 10, // top-level components text: 4000, // characters across all text textDisplay:4000

Sleep timer

?sleep 30 fades the music out and disconnects in thirty minutes. Range is hard-clamped to 1–600 minutes, with a live cancel button and a status readout that survives restarts.

See it in commands

Live source switching

Two buttons on the Now Playing card flip the server between Spotify and YouTube instantly. The choice is written to the settings store and mirrored onto the live player, so it survives a restart.

No-prefix commands

Allowlisted users type play ankhon mei teri and it just works. Strict first-token matching means “playing with the settings” stays ordinary chat — no command, no error, no reply.

25 filter presets

Nightcore, vaporwave, 8D rotation, karaoke, bassboostextreme — plus a 15-band equalizer. Filters reset to a clean slate before applying, then the player volume is restored.

Capabilities

Everything it does,
and why it does it that way.

Six feature groups, each one traceable to a file in the repository. No bullet point here is marketing dressing — if it is listed, it is in the code.

01 · Playback9 cmds

The part you actually feel

Search with a real fallback chain

Plain text goes ytsearch → ytmsearch → scsearch, each attempt in its own try/catch. A direct link bypasses search entirely and is handed to Lavalink as-is. Devanagari, roman Hindi, mixed script and zero-width junk are all normalised before the query leaves the bot.

Transport that never gets out of sync

Pause, resume, skip by amount, previous, replay, seek, forward, rewind, stop, disconnect — all guarded by requirePlayer and requireSameChannel so a command can never touch someone else's player.

A sleep timer that survives a restart

?sleep 30 clamps to 1–600 minutes, stores the deadline, shows a live countdown and a cancel button. ?sleep status reports what is pending.

02 · Queue14 cmds

Queue surgery, not queue hope

Paginated, interactive view

?queue renders ten tracks per page with working ‹ / › buttons. The pager is disabled cleanly when there is only one page — no dead arrows.

Every reorder you have ever wanted

Move a track, remove one, remove a range, jump straight to a position, shuffle, sort by title/duration/author, dedupe exact repeats — each one validates the index before touching the queue and reports a clean error instead of throwing.

Autoplay + save/restore

When the queue empties, ?autoplay pulls similar tracks so the room never goes quiet. ?queuesave / ?queuerestore persist a whole queue by name across restarts.

03 · Audio9 cmds

Sound, tunable

15-band equalizer

Twelve presets including bassboostextreme, gaming, fullsound and bettermusic — or set any single band's gain by hand.

Speed, pitch & rate

Independent timescale controls from 0.5× to 2.0×, re-applied safely so they compose rather than fight.

Lyrics from LRCLIB

?lyrics fetches synchronised text for the current track, or takes a query of its own. Long results are split across the 4000-character ceiling automatically.

04 · IdentityV2 cards

A bot that looks like a product

Every response goes through one renderer. The Now Playing card carries a cover, title, artist, clock and requester — plus exactly six controls: ‹ = › Stop Spotify YouTube. One live card per player, enforced by a single poster serialised behind a per-player lock, and deleted automatically when the queue ends.

postNowPlaying() trackKey() clearNowPlaying()
05 · Persistence11 stores

Nothing forgotten

Eleven atomic JSON stores — prefixes, 24/7 state, favourites, playlists, saved queues, history, settings, presence, bio and the no-prefix allowlist. Writes go to a temp file and rename, on a short debounce, so a container killed mid-write never leaves a truncated file. A corrupt file is backed up and the bot still boots.

06 · Operations/diag

Debuggable on purpose

/diag renders the whole internal state in one card, so you never have to open container logs to find out why an alias vanished. Registry collisions, per-category counts, the last slash registration attempt with its timestamp and per-guild error, and every Lavalink node's health all sit in four blocks.

Access is gated by diagAccess — manageguild by default (owner, Manage Server, or a developer), developer for owner-only, or everyone on a private server. The command is read-only: it never re-registers, never touches a player, never writes to disk.

The story · written from the source

There is a girl.
Her name is Shaly.

Everything on this website is named after her. Not because it sounded good, but because the bot was made for her, and you do not give something a stranger's name.

There is a line in the code that says it plainly. It runs every time someone types ?botinfo, and it has never been changed since the day it was written:

src/botinfo · "The story"

“Shaly is the name of the creator's girlfriend. This bot was inspired by her and made with love for her.”

That is the whole origin. No funding round, no roadmap deck, no launch thread. Somebody wanted a music bot that behaved well, because somebody else deserved one that behaved well.

What “made with love” actually means
in a codebase.

It means the boring parts got done. It means that when the last track in a queue finished, and Lavalink quietly never emitted trackEnd, the Now Playing card did not just sit there on the screen like an abandoned thing. A queueEnd listener was added. The card cleans itself up now.

It means that a search for a Hindi song typed in Devanagari, or in roman letters, or with a zero-width character stuck in the middle from a phone keyboard, still finds the song — because one source failing should never be the end of the request.

It means the sleep timer was built with a cancel button, because someone falling asleep mid-playlist should be able to change their mind at 1am without getting out of bed.

It was named after her

The display name, the component customId prefix, the tagline in every footer — all one constant in src/brand.js, so a rename stays consistent everywhere.

The tagline is hers too

“music, with love” sits under the name in every footer, and the public bio says “music, simply.” — both from the same file.

Then it got careful

66 commands, two-pass registry resolution, atomic JSON writes, 45 offline tests. Care, expressed as not breaking things.

And then it stopped being
just for one person.

The bot is hosted now. It sits on a Lavalink node, it answers in servers that have nothing to do with the two people it started with. Strangers type ?play and a song starts, and they have no idea where the name came from.

That is the good part, honestly. Something made for one person turned out to be useful to a lot of them — and it still carries her name in every footer, quietly, like a signature in the corner of a painting.

“music, simply. YouTube & Spotify, clean controls, and the songs you love.”

Changelog · from CHANGES.md

What changed,
and what did not.

Every release since the rename. The recurring sentence — “kuch bhi nahi toda” — is not a slogan; it is the actual acceptance criterion each release was tested against.

v15.3.0current

/diag — the internals, in one card

  • New diag command (/diag + ?diag, aliases diagnostics, selfcheck) rendering four blocks: registry, categories, slash registration, health.
  • Registry now records collisions in memory — recordCollision(), collisionReport(), aliasReport() — instead of only writing them to logs.
  • Slash registration status is tracked on every exit path: count, scope, guild names, timestamp, and per-guild error on failure.
  • New config key diagAccess (manageguild default) plus a Discord-native default_member_permissions gate, re-checked inside run() so the prefix path is safe too.
  • Read-only by design: never re-registers, never touches a player, never writes to disk. Self-test suite grew to 45 passing.
v15.2.1

The alias that ate the command

  • Reported: after ?anp granted no-prefix access, commands still did not run.
  • Root cause: the registry map was built in a single pass, so a later file's alias silently overwrote an earlier command's canonical name — move resolved to join, and h depended on load order.
  • Fix: new registerAll() with two passes — names lock first, aliases only fill keys nobody claimed, and a colliding alias is skipped with a warning instead of overwriting.
  • No command file was touched. 65 commands, all aliases, all behaviour unchanged.
v15.2.0

No-prefix commands

  • Allowlisted users can run any command without the prefix: play ankhon mei teri equals ?play ankhon mei teri.
  • Strict first-token matching against the live registry, so ordinary chat like “i want to play guitar” never triggers anything.
  • Everyone else is completely unaffected — no command, no error, no reply.
  • Grants persist to data/noprefix.json; ?anp / ?rnp / ?rnp list manage them. New src/dispatch.js is now the shared executor for both entry points.
v15.1.0

Now Playing card lifecycle

  • Bug: the card stayed on screen after the queue ended — because lavalink-client never emits trackEnd for the final track, only queueEnd. A queueEnd listener now handles cleanup.
  • Bug: a new song edited the old card instead of posting a new one. Fixed with a stable trackKey(); a new track deletes and reposts, the same track edits in place.
  • Bug: “track added” cards stacked up. Now exactly one live card per player.
  • Three permanent regression tests added — 34 passing at the time.
v15.0.0

Compact Shaly profile

  • Now Playing became a compact dark CV2 card: title, artist, duration, requester — and six controls.
  • /botinfo became a real slash command; ?stats remains an alias. The card carries the story, live stats, features and support link.
  • /bio and ?bio update the persisted bio, restricted to developerIds.
  • Joining servers receive a thank-you CV2 DM; mentioning the bot replies with quick-help.
v15 · search fix

Why ?p stopped playing nothing

  • search() was rewritten: query normalisation (zero-width, control chars, whitespace collapse) and an ordered fallback chain ytsearch → ytmsearch → scsearch, each attempt isolated in its own try/catch.
  • Direct links are handed to Lavalink untouched; a dead source can no longer kill the whole command.
  • No-result and node-unreachable now raise clean UserError messages instead of returning silently.
v14

Components V2, guild-scope slash

  • Every embed became a CV2 container with sections, separators, thumbnails and action rows.
  • Slash commands moved to guild scope so they appear instantly instead of waiting for global propagation — with automatic ghost cleanup of the old global set.
  • The bot was renamed Shaly (was Gaana), with the name living in exactly one place.

01 Run the bot

The bot is plain ESM Node — no build step, no transpiler. Extract the ZIP and install:

terminal
# inside the extracted shaly/ folder node --version # must be >= 18.17.0 npm install npm run check # 45 offline assertions, no Discord needed npm start

On a successful boot the log looks like this — three lines, in this order:

stdout
INFO (registry) Loaded 66 command(s) from commands INFO (boot) Starting Shaly v15.3.0 (Shaly • Components V2 • no-prefix • /diag) INFO (slash) Slash commands: registered 66 in guild <name> — guild scope, instant.
Two placeholders will stop the boot on purpose. If token still reads YOUR_DISCORD_BOT_TOKEN_HERE, or every Lavalink node still has a YOUR_LAVALINK_* value, the config validator logs the reason and exits with code 1. It refuses to start half-configured rather than failing later at the first ?play.

The ZIP you were given was scrubbed of credentials. If an older copy ever contained a live token, rotate it in the Developer Portal and change the Lavalink password with your node host before using it.

02 Lavalink node

Shaly is a Lavalink client — it does not decode audio itself. You need a Lavalink v4 server reachable from wherever the bot runs.

The URL form (recommended)

One environment variable replaces the whole lavalink.nodes[] array:

LAVALINK_URL format
lavalink://nodeId:password@host:port # real shape, port 2774 as in config.json lavalink://main:my-strong-password@lavalink.example.com:2774

When LAVALINK_URL is present, the file's node array is ignored entirely — so a leftover placeholder can never get merged in beside a real node. Multiple nodes are comma-separated.

Or the JSON form

config.json
"lavalink": { "nodes": [{ "id": "main", "host": "lavalink.example.com", "port": 2774, "password": "my-strong-password", "secure": false }] }

Sources need plugins

YouTube and SoundCloud work on a stock node. Spotify, Apple Music, Deezer and Yandex Music need the LavaSrc plugin on the node — Shaly hands those links over by name and falls back to a YouTube search built from the link if the source is unavailable, so the song still plays.

Search fallback order is fixed in src/source.js → SOURCE_FALLBACKS: ytsearch → ytmsearch → scsearch. SoundCloud is deliberately last — it is broken on some shared nodes, but still better than failing outright.

05 Slash commands register instantly

Global slash registration can take up to an hour to propagate, which makes a fresh deploy feel broken. Shaly therefore registers per guild, where commands appear immediately.

Guild IDs resolve in this order:

  1. config.json → slashGuildIds
  2. Environment: SLASH_GUILD_IDS (or GUILD_ID)
  3. Fallback: every guild the bot is already in — zero config needed

If none of those resolve, the bot prints a boxed warning telling you exactly what to add. It never fails silently.

Ghost cleanup

Leftover global commands from an older version are cleared once on startup, and per-guild commands this version no longer ships are deleted before re-registering. No duplicates, no /play twice in the picker, no dead entries.

06 Deploy this website

The site is one HTML file. No build, no dependencies, no folder structure. If you can drag a file into GitHub, you can ship it.

Fonts come from Google Fonts over HTTPS. Everything else — icons, logo, grain, gradients, the dashboard logic — is inline. There is no image folder to forget to upload.

Which file?

The package is two files: index.html at the root and api/config.js in an api/ folder. Vercel serves index.html at the domain root automatically and turns api/config.js into the /api/config endpoint. Keep both names exactly as they are.

How the page picks up config

Three sources, in order — the first one that answers wins:

  1. window.__SHALY_CONFIG__ — an inline object, if you inject it into the HTML
  2. /api/config — the serverless function below
  3. localStorage — whatever you typed into "Endpoint settings" in the dashboard

If all three are empty the site runs in demo mode: every dashboard value is labelled unavailable rather than filled with fake numbers.

The twelve-line function

Save as api/config.js next to index.html. Vercel turns it into /api/config automatically.

api/config.js
// Public config only. Never put a secret here. export default function handler(req, res) { res.setHeader("Cache-Control", "public, max-age=60, s-maxage=60"); res.status(200).json({ apiBase: process.env.SHALY_API_BASE || "", botName: process.env.SHALY_BOT_NAME || "Shaly", inviteUrl: process.env.SHALY_INVITE_URL || "", supportUrl: process.env.SHALY_SUPPORT_URL || "https://discord.gg/HrEaBy8dBU", guildId: process.env.SHALY_GUILD_ID || "1549441177550585960", clientId: process.env.SHALY_DISCORD_CLIENT_ID || "", pollMs: Number(process.env.SHALY_POLL_MS) || 15000, }); }

No package.json needed — this is a plain ESM handler. If Vercel asks, choose "Other" as the framework preset; the static file is served as-is.

08 GitHub → Vercel, in eight clicks

  1. Create a new repository on GitHub. Public or private, either works.
  2. Add file → Upload files, drag in index.html (and api/config.js if you want env vars), then Commit changes. On a phone, the GitHub mobile site supports the same upload flow.
  3. Go to vercel.com/new and import that repository. Sign in with GitHub if asked.
  4. Framework preset: Other. Build command: empty. Output directory: empty or .
  5. Open Environment Variables and add the keys from the table above. Mark anything with SECRET in its name as sensitive.
  6. Click Deploy. First build takes about twenty seconds because there is nothing to build.
  7. Open the deployment URL. The landing page should render immediately.
  8. Optional: Settings → Domains to attach your own domain. Vercel issues the certificate automatically.
Every later push to the branch redeploys automatically. Changing an environment variable requires a Redeploy from the Deployments tab — Vercel does not re-run builds on env edits.

Drop-in route

The whole thing, in about thirty lines

Paste this into index.js next to the existing app.get("/health"). It reads the manager the bot already has — it does not touch playback, and it is guarded so a missing player returns a clean playing:false instead of throwing.

index.js — after app.get("/health", …)
// Read-only snapshot. Requires DASHBOARD_TOKEN to be set, otherwise 503. app.get("/api/state", (req, res) => { const token = process.env.DASHBOARD_TOKEN; if (!token || req.headers["x-dashboard-token"] !== token) return res.status(401).json({ ok: false, error: "unauthorized" }); const guildId = String(req.query.guildId || config.slashGuildIds[0] || ""); const player = guildId ? lavalink.getPlayer(guildId) : null; if (!player) return res.json({ ok: true, playing: false, queue: [] }); const t = player.queue.current; res.json({ ok: true, playing: Boolean(t), guildId, track: t ? { title: t.info.title, author: t.info.author, duration: t.info.duration, position: player.position, uri: t.info.uri, artwork: t.info.artworkUrl, isStream: t.info.isStream, requester: t.requester?.id ?? null, } : null, paused: Boolean(player.paused), volume: player.volume, repeatMode: player.repeatMode, queue: player.queue.tracks.map((x) => ({ title: x.info.title, author: x.info.author, duration: x.info.duration, uri: x.info.uri, })), }); });
Never expose this without a token. Player state includes channel activity and requester IDs. DASHBOARD_TOKEN is required by the route above — if it is unset the route refuses to answer at all. Keep it server-side; the static site should call it through your own function, not from the browser.
CORS

Let the browser read /health

A page on shaly.vercel.app cannot read shaly-bot.onrender.com/health unless that origin is allowed. One middleware, before the routes:

index.js
const allowed = (process.env.CORS_ORIGINS || "") .split(",").map((s) => s.trim()).filter(Boolean); app.use((req, res, next) => { const origin = req.headers.origin; if (allowed.includes(origin)) { res.setHeader("Access-Control-Allow-Origin", origin); res.setHeader("Vary", "Origin"); } if (req.method === "OPTIONS") return res.sendStatus(204); next(); });

Then set CORS_ORIGINS=https://your-site.vercel.app on the bot host. Do not use * — the allowlist is the whole point.

Transport

Why the buttons are honest

The stock routes are read-only. A dashboard button that appears to skip a track but only closes a toast is a lie, so this site does the truthful thing instead:

  • Transport buttons are disabled until a write endpoint exists.
  • Each one copies the equivalent Discord command — ?skip, ?pause, ?stop — so the click still does something real.
  • Add a protected POST /api/control (token-gated, same pattern) and flip the buttons on by setting SHALY_CONTROL_ENABLED=true in the site config.
